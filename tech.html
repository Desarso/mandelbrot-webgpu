How this runs in a browser

Zooming into the Mandelbrot set past about 10−15 breaks double precision. Getting to 10−40 and beyond, at interactive speed, in a tab, takes four ideas stacked on top of each other. This page is what each one does and why it is necessary.

1. The problem with just zooming

Rendering the set means iterating z ← z² + c for every pixel and asking how long it takes to escape. The pixel's coordinate c needs enough digits to distinguish it from its neighbour. At a zoom of 10−40 two adjacent pixels differ in the 43rd decimal place. A double holds about 15. Every pixel on screen collapses to the same number and the image becomes a flat colour.

The obvious fix — do all the arithmetic in arbitrary precision — is far too slow. A 1280×720 frame at 20,000 iterations is roughly 18 billion big-number multiplications.

2. Perturbation: iterate once, reuse everywhere

Pick one point near the centre of the view, the reference, and iterate it in full precision — once. Call that orbit X₀, X₁, X₂, …. Every pixel is then described by how far it sits from the reference, δ = c − c_ref, and how far its orbit has drifted, w = z − X. Subtracting the two recurrences gives an exact identity: 

w ← 2·X·w + w² + δ

Nothing has been approximated. But the numbers involved are now small — differences rather than positions — so they fit in ordinary floats even though the coordinates they came from do not. One expensive orbit, then millions of cheap pixels.

Two details make it work in practice. The reference orbit must be genuinely arbitrary precision, and the per-pixel delta has a dynamic range no f32 can hold — it starts around 10−40 and grows to order 1 before escaping.

3. Arbitrary precision on the GPU

The reference orbit is computed by a WebGPU compute shader in two's-complement fixed point: an integer spread over up to 256 u32 limbs, scaled by 2−32(n−1). That is up to about 2,450 decimal digits.

Fixed point, not floating point

Every sample of a reference orbit satisfies |z| < 4 or it has already escaped, and |c| < 2. There is nothing for an exponent to do. Dropping it makes addition and subtraction plain carry chains with no alignment step.

WGSL has no 64-bit integers

Multiplication needs 32×32→64. WGSL has no u64, so it is built from four 16-bit partial products, with the middle sum's carry tracked by hand: 

let mid = p01 + p10;                        // may carry out of 32 bits
let midCarry = select(0u, 0x10000u, mid < p01);
let lo = p00 + (mid << 16u);
let loCarry = select(0u, 1u, lo < p00);
hi = p11 + (mid >> 16u) + midCarry + loCarry;

One workgroup, not a grid

z ← z² + c is strictly serial: iteration n+1 needs iteration n. The only parallelism available is inside each big-number operation, where 256 threads each own a column of the multiplication. Keeping the whole recurrence in a single workgroup means barriers can be used instead of the grid-wide synchronisation WebGPU does not have, and one submission can advance thousands of iterations without a round trip to the CPU.

The high-precision state never leaves the GPU. Each batch returns a four-word status buffer and nothing else.

4. Deltas that carry their own exponent

The reference samples are order 1 and fit in f32. The per-pixel delta does not, so it is carried as a mantissa and an explicit binary exponent, renormalised every iteration. This is the single thing that separates the two rendering paths here:

WebGL2 fallbackWebGPU
Reference orbitCPU, decimal.js, uploaded as a textureGPU-resident fixed point
Per-pixel deltaplain f32mantissa + exponent
Depth limitspan 10−34set by limb count, not the renderer

The WebGL limit was measured rather than assumed: 10−34 renders correctly and 10−36 collapses, as the deltas fall into subnormal range and underflow to zero.

5. Skipping most of the work

While the delta stays far below the reference, the w² term is negligible and the step is linear. A whole range of iterations then collapses into a single polynomial, which can be precomputed once per orbit and applied per pixel: 

w_out = A·w + B·δ + C·w² + D·w·δ + E·δ²

Keeping only A and B is the usual bilinear approximation. Carrying the second-order terms pushes the first neglected term from quadratic to cubic, so the same error budget allows an entry delta larger by roughly its square root — many more pixels take many longer skips.

Steps are built in doubling levels — 8, 16, 32, … iterations — and each pixel greedily takes the largest one its delta still fits inside. Measured at a zoom of 2.8×1040: 96.9% of iterations skipped, 21× faster, and the image is bit-identical to the unapproximated render.

Why the coefficients need exponents too. A is a product of ~2X terms over the whole range, and over a few thousand iterations it routinely reaches 10700 while the matching validity radius underflows to zero. Stored as plain doubles the coefficient becomes Infinity and every radius derived from it becomes NaN. It is the product that stays sane, never the factors.

6. Finding somewhere worth looking

Zooming by hand past about 10−30 almost always lands in a smooth region where every pixel escapes within an iteration or two of every other — correct, and completely dull. The interesting places are the nuclei: centres of period-p minibrots, where the p-th iterate returns exactly to zero.

Newton's method converges on those quadratically, using the companion recurrence D ← 2zD + 1 for the derivative. A standard size estimate then says how far to zoom in. Sanity check: applied to the period-2 bulb it returns 0.5, which is that bulb's actual diameter.

7. Colouring

Escape counts give the classic bands. The other mode is analytic distance estimation: the orbit carries its own derivative, and on escape 

distance = 0.5 · |z| · ln|z| / |dz/dc|

normalised against the width of one screen pixel so the banding keeps the same visual scale at any depth. The base-2 logarithm of that is a height field, and its screen-space gradient drives a normal-map lighting pass — diffuse plus a Blinn–Phong highlight. Nothing is displaced; it only reads as a surface.

The derivative comes for free from the approximation table: D ← 2zD + 1 is the same recurrence as the delta with δ = 1, so the same A and B coefficients advance it across a skipped range.

Palette mixing and lighting are done in linear light, with a single gamma encode at the end, and up to 3×3 supersampling.

8. Where all of this comes from

Almost nothing here is original. Deep Mandelbrot zooming was worked out over about fifteen years, mostly by people posting derivations on a forum and giving the code away, and this renderer is an implementation of their results. The table is what each idea is and who it is due to.

IdeaDue to
Perturbation. One high-precision reference orbit, every other pixel tracked as a low-precision offset from it. Section 2. K. I. Martin, Superfractalthing Maths (2013) — the paper that made deep zooming practical, and the origin of the Δ-iteration used here.
Glitch detection. Noticing when a pixel's offset has grown large enough that the reference no longer describes it. Pauldelbrot, on fractalforums (2014). The criterion is a comparison of |z| against the reference's magnitude.
Rebasing. The fix this renderer uses instead: when |z| < |δ|, restart the pixel against the beginning of the same orbit. No glitch list, no second reference, no iterative repair. Zhuoran, on fractalforums.org (2021). It replaced a decade of increasingly elaborate glitch-correction machinery with three lines.
Bilinear approximation. Collapsing long runs of iterations into one polynomial step, with a validity radius. Section 5. Zhuoran (2021), extended and written up in detail by Claude Heiland-Allen. The second-order form used here follows the same construction.
Distance estimation. The derivative of the orbit gives the distance to the set, which is what makes thin filaments visible at all. Section 7. Hart, Sandin and Kauffman (1989) for the general method on distance-estimated fractals; the Mandelbrot form and its practical use popularised by Iñigo Quílez.
Nucleus finding. Newton's method on fp(c) = 0 to land exactly on a minibrot, plus the size estimate that says how far to zoom. Section 6. Classical Douady–Hubbard theory; the size estimate and the practical Newton iteration from Claude Heiland-Allen and Robert Munafo's Mu-Ency.
Arbitrary precision on a GPU. Fixed-point limbs, an emulated 64-bit multiply, and a serial orbit run inside a single workgroup. Section 3. FractalShark, by Matt Renzelmann, which is where the GPU-resident approach was taken from. This project is GPLv3 because of it. Its own approximation code came by way of Kalonakis Christos's Fractal Zoomer.
The colouring. Distance estimate to a height field, cyclic palette, screen-space normal for pseudo-3D relief. Maths Town's The Hardest Trip, which is the look this reproduces. Cosine palettes are Iñigo Quílez's.

Two implementations are the reference points for anyone doing this seriously: Kalles Fraktaler, started by Karl Runmo and later maintained by Claude Heiland-Allen, and FractalShark. Both are far more capable than this page's renderer. The forum threads at fractalforums.org are where most of the above was derived in public, usually years before it appeared in any paper.

  • Claude Heiland-Allen, Deep zoom theory and practice (2021) — the clearest single write-up of perturbation, rebasing and bilinear approximation together. The rest of the blog covers distance estimation, nucleus finding and size estimates.
  • Robert Munafo, Mu-Ency — the encyclopaedia of Mandelbrot structure: periods, sizes, naming.

  • John Milnor, Dynamics in One Complex Variable — the underlying theory, for why any of the above is true rather than merely observed.

Known limits

The schoolbook multiplier is O(n²), which is fine to the 256-limb top profile but is where an NTT would belong — at eight limbs, which is what almost every view actually uses, it would be far slower. Orbits are stored uncompressed; at 24 bytes a sample that is a few megabytes, and not where the time goes. At a minibrot nucleus the reference orbit returns close to zero every period, forcing a rebase each time, and after a rebase the delta is order 1 and too large for any approximation step — so those views are correct but slower than their surroundings.
